- ビルド: @wordpress/scripts 35。開発用の公式パッケージを明示し、実行時はコア同梱 API を使用。

## 自動確認の実行方法

README のコマンドを使用する。公開出力の比較は `npm run test:non-interference`。この確認は検証用投稿を公開し、プラグインを一時無効化して比較した後、finallyで再有効化・検証投稿削除を行う。作業中の利用者がいないローカル環境で実行する。

E2E は一部のフィクスチャ作成・CSS属性更新に公開 `wp.data` API を使用し、設定画面やパレット、本文入力は実際の画面操作で確認する。全てのCSS編集操作をマウスのみで実行した検証ではない。

## 制限と未検証項目

- テンプレートパーツや同期パターンは標準ブロックラッパー経由で判定するが、各編集モードの網羅的な操作確認は未実施。
- マウスのドラッグ操作、スクリーンリーダーの実機読み上げ、全管理画面配色、最新 Gutenberg プラグイン併用、複数ブラウザ、マルチサイト、PHP 7.4の実行確認は未実施。
- `edit_css` のないユーザーも可視化設定を利用できることを統合確認。CSSを含む記事をそのユーザーが保存した際のコアによるCSS除去は回避しない。
- 保存完了前のページ離脱では設定が残らない場合がある。保存失敗時は通知から再試行する。別タブの設定は自動同期せず、最後の保存を採用する。
- 可視化を有効にしたままプラグインを管理画面で停止した場合、既に開いているエディターのJSは再読み込みまで残る。再読み込み後は独自UIと表示が消える。
- CSSの構文チェックは対象外。コメントだけの文字列や構文不正の文字列も、空でなければ検知する。
- 選択・ホバー・ドラッグ時は標準UIを優先する。子孫のCSSを親には通知しない。インジケーターは選択ブロックだけ。
- 追加のCSSマーカー、CSS欄へのジャンプはMVPでは採用していない。
- 後続機能は [roadmap.md](roadmap.md) の9件のGitHub Issueを参照。
